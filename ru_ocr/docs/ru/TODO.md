## 4. Отдельный репозиторий для ru_ocr

В форке лежит вся библиотека PaddleOCR, и работа по обучению в ней теряется. Вынести `ru_ocr/` (конфиги, словари,
скрипты, инструменты, ноутбуки, тесты, документацию) в свой репозиторий без библиотеки, а ветку
`feat/ru-ppocrv6-small-training` убрать из публичного форка.

- **PaddleOCR из зафиксированного релиза плюс патч.**
  - В репозитории лежит `patches/paddleocr-v3.7.0.patch`: наши изменения ядра, `git diff` всего, что вне `ru_ocr/`.
  - `scripts/setup_env.sh` клонирует тег `v3.7.0` и делает `git apply`.
  - Патч, а не копии файлов целиком. Если новый релиз поменяет те же места, `git apply` откажется с ошибкой, а не
    затрёт молча исправления PaddlePaddle.
  - Когда PR из пункта 3 вольют и выпустят в релизе, его часть уходит из патча.
- **Проверено 2026-10-26:**
  - 16 файлов ядра, которые мы меняем, одинаковы в `v3.7.0` и в `main` (`dab3fe3`, основа ветки); различаются
    только два файла документации `text_recognition`;
  - весь diff ядра (25 файлов с тестами и документацией, ~4 000 строк) ложится на `v3.7.0` без конфликтов.
- **Что завязано на дерево PaddleOCR и требует правки:**
  - `scripts/run_train.py`, `benchmark.py` и ноутбуки вызывают `tools/train.py`, `tools/eval.py`,
    `tools/export_model.py`;
  - `tools/convert_torchocr_rec.py` и `validate_models.py` импортируют `ppocr`;
  - `tests/conftest.py` кладёт корень репозитория в `sys.path`;
  - ноутбуки клонируют `REPO` / `BRANCH` и берут пути `ru_ocr/...`.

  Вероятно: новый репозиторий рядом с пропатченной копией PaddleOCR, путь к ней в одной переменной.
